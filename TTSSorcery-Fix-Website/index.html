TTSSorcery-Fix

The fix variant of the TTSSorcery SillyTavern extension. It does the same job, multi-speaker, multi-emotion text to speech generated through Zyphra's API as a reply streams, but each string has been tested and adjusted until the instrument sounds as one again: a reworked index.js, an added model_instructions.md, and its own test suite.

How it works

  1. A prompt is injected to make the AI add special text to speech markers to the text: §c:Character|happy.mp3|e1:0.8§
  2. These markers tell the extension who is speaking, which voice file to use, and in what emotion.
  3. The extension processes these markers and sends them to Zyphra's API, over HTTPS at api.zyphra.com/v1/audio/text-to-speech.
  4. Zyphra returns audio files that are played in order.

It uses the method and some code and prompts from p-e-w/sorcery, attributed in the repo. It is NOT integrated or compatible with SillyTavern's built in text to speech, and only works with chat completions for now.

What the fix pass set right

  • The stylesheet ships. Earlier revisions declared style.css in the manifest but did not include the file, so the stylesheet would have failed to load. It is present here, and the manifest declares index.js and style.css, both on disk.
  • The Zyphra call runs over HTTPS. Earlier revisions used plain HTTP, which would have sent the API key unencrypted.
  • Handlers register once. The CHAT_COMPLETION_PROMPT_READY and STREAM_TOKEN_RECEIVED handlers are registered a single time; earlier revisions registered them twice, which could inject the instructions twice.
  • Presets work on a fresh install. Presets ship with a seeded Default preset, and the settings panel carries the preset controls (list, new, delete, export, import) the handlers bind to. Earlier revisions had no presets field and no controls, so the preset handlers threw on a fresh install.
  • A stream start no longer throws. The soft queue reset used to read a flag that was never defined, so the reset died inside the host event dispatch every time a stream began.
  • The instructions stand alone. model_instructions.md holds the standalone copy of the TTS marker instructions template the extension uses.

Set it up

  1. Get a Zyphra API key (the free tier gives 100 minutes a month).
  2. Add your API key in the extension settings.
  3. Upload at least one voice sample for the Narrator.
  4. Add character voices as needed.
  5. Enable the extension.

Features carried over from the extension: voice cloning from any audio sample, audio variants per emotion with no limit, emotion values across eight emotions (Happiness, Sadness, Disgust, Fear, Surprise, Anger, Other, Neutral), six languages (English, Japanese, Chinese, French, German, Korean), and preloading so playback does not pause mid generation. Auto generation works while streaming is enabled; the wand icon generates manually.

The tests

node --test test/ttssorcery.test.mjs test/presets-import.test.mjs

14 tests in the test/ folder, run with Node 20 or newer. test/harness.mjs builds the fake host tree the extension imports expect, and the suite runs the real index.js against that stub SillyTavern host. It covers preset seeding and the preset panel actions, instruction injection, stream resets, message parsing and segmentation, the Zyphra request bodies, voice fallback, and queue drain.

The files

index.js, the reworked extension (109,419 bytes, against 111,637 in the extension repo). manifest.json, the extension manifest, identical at 256 bytes to the extension repo's. style.css, the extension styles. model_instructions.md, the marker instructions template. test/, the harness and suite. LICENSE, the MIT license. The sibling repo is TTSSorcery-Extension; the full notes are in the repo README.

One string at a time is tested, adjusted, and set back in tune with all the others, which is what a fix pass does to a chorus of generated voices.
